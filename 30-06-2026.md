# Mentor Meeting and Dashboard Review

## Objective

The objective of this phase was to conduct a mentor meeting and review the current Dashboard page of SkillLens AI.

The meeting focused mainly on understanding the dashboard, checking the purpose of each KPI and graph, identifying bugs, and noting improvements required before the final project review.

---

# Background

Previous phases focused on:

* Frontend refinement
* Feedback section addition
* Dashboard improvement

By this stage, SkillLens AI had a working website structure, but the mentor review for this meeting focused only on the Dashboard page.

The main goal was:

```text
Critically review the Dashboard page and identify improvements in KPIs, graphs, bugs, and overall clarity.
```

---

# Mentor Meeting Summary

A meeting was held with the mentor to review the SkillLens AI Dashboard.

During the meeting, the dashboard was explained section by section. The mentor reviewed the page critically and asked questions about the purpose of the KPIs and graphs.

The discussion focused on:

* Dashboard layout
* KPI cards
* Graph selection
* Chart readability
* Purpose of each visual
* Bugs and fixes
* Data clarity
* User understanding
* Overall dashboard presentation

The meeting helped identify that the dashboard should not only look visually good, but every metric and graph should clearly support the project objective.

---

# Dashboard Review

The Dashboard page was reviewed as the main overview page of SkillLens AI.

The dashboard is important because it is the first page users see after opening the platform.

It should quickly explain:

* What SkillLens AI does
* How many skills are being analyzed
* What industries are covered
* Which skills are growing
* Which skills are risky
* What the forecast trends show
* How workforce intelligence is summarized

The mentor reviewed the dashboard from the perspective of a first-time user and checked whether the information was understandable.

---

# KPI Review

The KPI cards were reviewed carefully.

The mentor suggested that the KPI cards should be clear, meaningful, and directly connected to the project.

Focus areas discussed:

* KPI names should be easy to understand
* Values should be formatted properly
* Metrics should not look random
* Each KPI should explain something useful
* The dashboard should not include unnecessary numbers
* KPIs should reflect the actual project data

Possible KPI labels discussed:

```text
Skills Analyzed
Industries Covered
Average SES Score
High-Risk Skills
Growing Skills
Forecast Confidence
```

These KPI names are clearer because they directly connect with SkillLens AI and HSEP.

---

# Graph Review

The mentor critically analyzed the dashboard graphs one by one.

For each graph, the mentor asked:

```text
What is the purpose of this graph?

What is it trying to show?

Why is this useful for the user?

Is the graph needed on the dashboard?

Can the user understand it without extra explanation?
```

This was an important part of the review because the dashboard should not include graphs only for design. Every graph should communicate a useful insight.

---

# Graph Improvement Suggestions

Several improvements were suggested for the dashboard graphs.

Focus areas:

* Improve graph titles
* Add clearer axis labels
* Fix confusing values
* Use better chart types where needed
* Avoid unnecessary or repetitive graphs
* Make charts easier to understand
* Add short explanations below important graphs
* Make sure graph values are properly scaled
* Ensure each graph supports the dashboard purpose

The mentor suggested that graphs should be simple, readable, and meaningful.

---

* Explain the purpose of every dashboard graph
* Improve unclear KPI names
* Update confusing KPI values
* Fix graph labels and scaling
* Remove graphs that do not add enough value
* Make the dashboard easier for a first-time user
* Keep the Methodology page clear
* Add before and after screenshots for improvements
* Fix dashboard bugs before the final review

This feedback will guide the next dashboard refinement phase.

* Every dashboard graph should have a clear purpose.
* KPIs should be understandable at first glance.
* A dashboard should summarize the project clearly, not overload the user.
* Mentor review helps identify unclear parts that may be missed during development.
* Chart titles, labels, and scaling are very important.
* Before and after screenshots are useful for showing improvement.
* The Methodology page is strong and should remain clear.
* The Dashboard page needs to be simple, meaningful, and review-ready.

# RAG Retrieval Pipeline Research

## Objective

The objective of this phase was to research how a Retrieval-Augmented Generation (RAG) pipeline can be designed for the Human Skill Extinction Predictor (HSEP) Career Advisor.

After researching knowledge base design, the next focus was understanding how the AI Career Advisor can retrieve relevant HSEP information before generating career guidance.

This phase was research-focused only. No implementation or development work was performed.

---

# Background

Previous phases focused on:

* LLM and RAG research
* Career recommendation system research
* AI Career Advisor architecture research
* HSEP knowledge base design research

The knowledge base research helped identify what information should be stored for retrieval.

The next research question was:

```text
How can the AI Career Advisor retrieve the most relevant HSEP knowledge for a user query?
```

---

# Need for a Retrieval Pipeline

The AI Career Advisor should not generate answers from memory alone.

Before answering, it should retrieve relevant information from HSEP outputs such as:

* Skill profiles
* SES scores
* Forecast results
* Skill archetypes
* Industry analytics
* Related skills
* Recommendation signals

A retrieval pipeline is needed to connect user questions with the correct project knowledge.

# Basic RAG Pipeline

A basic RAG workflow was studied.

The process includes:

```text
User Query
        ↓
Query Understanding
        ↓
Retrieve Relevant Knowledge
        ↓
Build Context
        ↓
Send Context to LLM
        ↓
Generate Grounded Answer
```

In HSEP, the retrieved knowledge should come from skill intelligence, forecast intelligence, industry analytics, and recommendation logic.

---

# Query Understanding

The first part of the retrieval pipeline is understanding the user query.

Example queries:

```text
Is Python future-proof?

What should I learn after SQL?

Compare Power BI and Tableau.

Which skills are risky in Data Analytics?

Give me a roadmap for Data Science.
```

Each query has a different intent.

Possible intent categories:

* Skill evaluation
* Skill recommendation
* Skill comparison
* Industry guidance
* Career transition
* Roadmap generation

Understanding intent helps the system retrieve the correct type of knowledge.

# Metadata Filtering

Metadata filtering was identified as important for improving retrieval accuracy.

Useful metadata fields include:

* Skill category
* Industry
* Risk tier
* Forecast trend
* Archetype
* Confidence level
* Knowledge type

Example:

```text
User Query:
Which AI skills are growing?

Useful Filters:
Industry = AI & Machine Learning
Forecast Trend = Growing
Knowledge Type = Skill Profile
```

This helps the system retrieve only relevant information instead of searching the entire knowledge base blindly.

---

# Context Construction

After retrieving relevant knowledge, the system should create a clean context for the LLM.

The context should include:

* Direct facts
* Relevant scores
* Forecast information
* Industry relevance
* Recommendation signals
* Short explanations

Example context:

```text
Python has a high SES score, strong demand,
future-proof archetype, positive forecast trend,
and strong relevance in Data Science, AI & Machine Learning,
and Software Engineering.
```

This context allows the LLM to generate a grounded and explainable answer.

# Reducing Hallucinations

A key reason for using RAG is to reduce unsupported AI answers.

The advisor should:

* Retrieve HSEP data before answering
* Use only available project evidence
* Avoid inventing scores
* Mention uncertainty when data is limited
* Use forecast confidence where available
* Explain the reason behind each recommendation

This makes the AI Career Advisor more reliable.

---

# Retrieval Quality Considerations

Good retrieval depends on:

* Clean knowledge chunks
* Proper metadata
* Clear skill names
* Consistent terminology
* Strong query understanding
* Relevant context selection

If retrieval is poor, the final AI response may also become weak.

Therefore, retrieval quality is a major part of the future Career Advisor system.

---

# Key Learnings

* RAG requires both a knowledge base and a retrieval pipeline.
* Query intent detection helps retrieve more relevant information.
* Metadata filtering improves accuracy.
* HSEP knowledge should be converted into retrieval-friendly chunks.
* The LLM should explain retrieved intelligence, not invent career advice.
* Retrieval quality directly affects answer quality.
* RAG can make the Career Advisor more trustworthy and explainable.
